#+TITLE: A single-page view in pdf-roll

Started 2026-10-04 on =feat/single-page-roll=, a branch from =feat/async-render=.  File and line references are to that branch as of 2026-10-04.  This is step 1 of the plan at the end of =DESIGN-async-render.org=: write down what the single-page experience is, before building it.

* Goal

pdf-roll becomes the main mode.  The single-page experience of plain =pdf-view-mode= becomes an option within it, built on the machinery of =feat/async-render=: computed geometry, placeholders, the asynchronous render, the revert that keeps pages, the generation guard and reshaping.  Then the plain-mode path is deleted.

* Plain mode today

=pdf-view-mode= was written in 2013--2014 on the model of =image-mode=.  Each window shows one page as one image on one overlay that spans the whole buffer (=pdf-view-display-image=, =pdf-view.el:1494=).  Scrolling within the page is image-mode's vscroll and hscroll; turning a page replaces the image.  A page is redrawn after a window resize from =window-configuration-change-hook= (=pdf-view-redisplay-some-windows=).

* The single-page experience: checklist

What the single-page view must do, taken from =pdf-view-mode-map= (=pdf-view.el=) and the commands it binds.  "Roll today" says what continuous mode does with the same key; "?" marks behaviour not yet checked.

** Display

| Item | Plain mode | Roll today |
|------+------------+------------|
| One page per window | yes | as many pages as fit |
| =W= fit width, =H= fit height, =P= fit page | the page fills the window that way; =P= shows the whole page | same sizes; the next page shows below |
| =+= =-= =0= zoom | rescale the page | same |
| A page narrower than the window | centred | centred |
| A page wider than the window | hscroll | hscroll by image-mode's commands, a column per =C-f=; kept within the widest drawn page since 2026-10-04 (=check-hscroll=) |
| =s m=, =s b=, =s r=, =s c= slices | crop the page | same |
| =R= rotate | rotates the page | same |
| Several windows on one buffer | each shows its own page | each scrolls on its own |
| Window resized | the page is redrawn at the new size | same, from =pdf-roll-pre-redisplay= |

** Moving

| Keys | Plain mode | Roll today |
|------+------------+------------|
| =n=, =p=, =<next>=, =<prior>= | next or previous page, at its top | same |
| =M-<=, =M->= | first, last page | same |
| =M-g g= (=goto-line=), =M-g l= | go to page, to label | same |
| =SPC=, =S-SPC=, =DEL= | scroll a screen; at the page's edge turn the page, landing at the top (forward) or the bottom (backward) | scroll a screen across pages (one line before the decision below) |
| =C-n=, =C-p=, =<down>=, =<up>= | scroll a line; at the bottom or top turn the page if =pdf-view-turn-page-at-top-and-bottom= | scroll a line across pages |
| =RET= | =image-next-line=: a line down, no page turn | undefined since 2026-10-04; users can bind it |
| Mouse wheel | =pdf-view-scroll-up-or-next-page= with a line count: turns the page at the bottom or top if =pdf-view-turn-page-at-top-and-bottom= | =pdf-roll-scroll-forward= across pages |
| At fit-height or fit-page | any scroll turns the page (=pdf-view.el:977= and =1002=, a workaround for rounding) | scrolls across pages |
| =S-<next>=, =S-<prior>= | not bound | scroll a screen across pages |

=pdf-view-turn-page-at-top-and-bottom= (default t; called =pdf-view-continuous= before 2026-10-04, which stays as an obsolete alias) decides whether line scrolling and the wheel turn the page past its bottom or top.  With nil, only =SPC= and =DEL= without a prefix argument do.

** Features that read the page or the position

| Feature | Plain mode | Roll today |
|---------+------------+------------|
| Text selection, =M-down-mouse-1= rectangle, =C-down-mouse-1= extend | on the page shown | on the page under the mouse (=pdf-view-mouse-set-region=, three branches) |
| =C-c C-i= extract region image | the region's page | same |
| =m=, ='= registers | page and position within it | page and position, in both views (=check-position=) |
| Bookmarks | page, slice, size and =origin= (the position in the page), restored with =image-set-window-vscroll= | the same record; =origin= restored in both views (=check-position=) |
| Isearch | moves through the pages | same; wrapping fixed in =3f235fc= |
| Links, =pdf-links-action-perform= hints | on the page shown | on every page drawn (=pdf-links.el:241=) |
| SyncTeX backward search, mouse | the page shown | the page under the mouse (=pdf-sync.el:285=) |
| Annotations: show, add text, read | the page shown | the page given (=pdf-annot.el:1028=, =1146=, =1633=) |
| =pdf-util-required-vscroll= (scroll to show an edge) | image vscroll | pixel edges (=pdf-util.el:396=) |
| Dark, midnight, themed, printer modes | redraw the page | redraw the pages |
| Mode line: page, size indication | the page shown | the current page; draws nothing |
| History, outline, occur | go to a page | same |

* Decisions

- 2026-10-04: =SPC=, =S-SPC= and =DEL= scroll a screen in roll mode, as in plain mode; users who want a line can rebind them.  Done in the commit that adds this section.
- 2026-10-04: upstream #345 is left for last.
- 2026-10-04: =RET= is not bound by pdf-tools; it was =image-next-line=, a line scroll that never left the page.
- 2026-10-04: the end state.  =pdf-view-mode= is the continuous view, drawn by the machinery of =pdf-roll.el=.  The single-page experience is a minor mode on top of it, =pdf-view-single-page-mode=; users who want it add it to =pdf-view-mode-hook=.  The plain-mode path is deleted.
- 2026-10-04: =pdf-view-roll-minor-mode= is then either deleted or kept as an obsolete name that warns when used -- never one that silently does nothing.
- 2026-10-04: in the single-page view, =C-n= scrolls one line down the page; if the page has no line left to scroll, because its bottom is already at the bottom of the window, =C-n= turns to the next page if =pdf-view-turn-page-at-top-and-bottom= is non-nil, and otherwise does nothing.  =C-p= is the same at the top.  The rule does not depend on the page fitting the window.  Plain mode instead scrolls a page that fits up into blank space below it; that is not reproduced.

* Known issues to check

- Upstream #345, last: pdf-roll clobbers other overlays that carry a =window= property, such as the region highlight.
