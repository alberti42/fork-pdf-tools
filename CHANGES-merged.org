* Fixes with no pull request yet

Each of these lives on its own branch off =master=, so any of them can be sent as a pull request on its own.  The branch is named after each group.

** Compressed, encrypted or inside-archive PDFs, on top of #335

On =fix/compressed-encrypted-pdfs=, which also carries @piater's two commits.

- fix(pdf-view): keep the server's copy in step when saving.  Saving a .pdf.gz twice, with one highlight added each time, ended with a file that had the second and not the first.
- fix(pdf-view): write through the file handlers, not through the buffer.  Saving no longer replaces the buffer, so it no longer costs the page overlays under ~pdf-view-roll-minor-mode~.
- fix(pdf-view): give the write epa's settings from this buffer.  Saving an encrypted PDF stopped to ask for the recipients on every save.
- fix(pdf-view): ask for ~epa-inhibit~ the way that does not warn.
- Tests for saving a compressed, a gpg-encrypted and an in-archive document.

** pdf-roll

- fix(pdf-roll): redisplay every window when WINDOW is t.  Toggling ~pdf-view-midnight-minor-mode~ from another window, or from a hook, did not redraw the PDF until its window was selected.  Reported upstream as [[https://github.com/vedang/pdf-tools/issues/373][issue 373]].  (branch =fix/roll-redisplay-all-windows=)
- fix(pdf-roll): put point on the page the window is set to start at.  A window configuration saved before a revert, and restored after it with ~jump-to-register~, showed a blank window until you scrolled.  (branch =fix/roll-point-after-restore=)
- fix(pdf-roll): give ~setq-local~ one pair at a time.  pdf-roll.el did not byte-compile on Emacs 26.3.  (branch =fix/roll-setq-local-one-pair=)

** Mode line

A mode-line construct is evaluated while Emacs is displaying, so it may neither draw a page nor wait for the server: a wait runs timers and other processes' filters and sentinels, and ~display_mode_line~ holds a pointer into the glyph matrix across the construct, so Lisp that reallocates the matrix there -- ~set-window-vscroll~ does -- leaves it dangling and Emacs crashes.  Reported as Emacs [[https://debbugs.gnu.org/cgi/bugreport.cgi?bug=81903][bug#81903]].

- fix(pdf-info): run no timers while a synchronous query waits.  ~accept-process-output~ is given an integer JUST-THIS-ONE, so the wait reads its own process and nothing else.  Filed as [[https://github.com/vedang/pdf-tools/pull/374][#374]].  (branch =fix/info-query-no-timers-while-waiting=)
- fix(pdf-misc): measure only the page the window already shows.  ~pdf-misc-size-indication~ asked ~pdf-view-image-size~, which draws the page under ~pdf-view-roll-minor-mode~ when the window has not drawn it yet.  (branch =fix/misc-size-indication-no-error=, on top of #365)
- fix(pdf-view): read the mode-line data when the document opens.  Both ~:eval~ forms in ~mode-line-position~ asked the server -- the page labels on every redisplay, the number of pages after every revert -- and both ~ignore-errors~ are gone with them.  (branch =fix/mode-line-no-server-query=)
- test(pdf-info): answer the query from the filter, not from a timer.  @benthamite's tests in #370 hang once the first of these lands.  Only on =merged=: it belongs with whichever of the two reaches upstream second.

** Other

- fix(pdf-util): convert the page the window is showing.  ~pdf-annot-edit~ failed in a window that had only drawn the page in roll mode: =Wrong type argument: char-or-string-p, nil=.  (branch =fix/convert-page-displayed-image=)
- fix: use ~when-let*~, which ~when-let~ became, and fix(pdf-roll): use ~if-let*~, which ~if-let~ became.  Emacs 31 made both obsolete.  (branch =fix/when-let-obsolete=)
- fix(pdf-view): resize the document, not one page's image.  =C-<wheel-up>= and =C-<wheel-down>=, from ~image-map~, resized the image of the page under the pointer, which kept that size until it was drawn again.  On macOS, touching the trackpad with Control held, as when typing =C-x s=, sends one.  They now do nothing, and =i += and =i -= enlarge and shrink the document.  =i r=, =i h=, =i v=, =i c= and =i x= rotated, flipped or cropped one page's image in the same way, and the document did not record it; they are now undefined.  (branch =fix/view-image-zoom-keys=)
- fix(sync): signal a user-error when the buffer visits no file.  Forward search from a buffer that visits no file, such as a magit index buffer, failed with =Wrong type argument: stringp, nil=.  (branch =fix/sync-forward-no-file=)
- feat(pdf-history): keep one provisional item while browsing a list.  While a follow mode moves the document, the history keeps one item for where browsing landed and replaces it on the next move, so =B= returns to the position you were reading.  This changes what the history records, so it will get its own pull request, after #371.  (branch =feat/history-provisional-entries=)

* Features built on =merged=

These branches start from =merged=, not from =master=.  The NEWS section of version 1.4.0 lists what they change for the user.

- =feat/async-render=: pages are rendered without waiting for the server.  A page not rendered yet shows a blank placeholder of its size, and the page replaces it when the server has rendered it.  Reverting a document keeps the pages on screen until their new renders arrive.  The branch also requires Emacs 27.1.  Design in =dev/DESIGN-async-render.org=.
- =feat/single-page-roll=, on top of =feat/async-render=: ~pdf-view-mode~ scrolls continuously, as ~pdf-view-roll-minor-mode~ did in 1.3.0.  New minor mode ~pdf-view-single-page-mode~ shows one page at a time, as ~pdf-view-mode~ did before.  ~pdf-view-roll-minor-mode~ is obsolete: it warns once per session and does nothing.  The mouse wheel and the trackpad scroll by what they report, and PageDown and PageUp scroll ~pdf-view-page-key-lines~ lines.  Design in =dev/DESIGN-single-page-roll.org=.
- =fix/save-redraw-pages=: fix(view): draw the pages again whenever the document is closed.  After a save, the pages on screen stayed stale: text could not be selected and clicks on annotations did nothing.
- =feat/documents-in-memory=, on top of =fix/save-redraw-pages=: epdfinfo reads a document into memory when opening it, so writing over its file -- a save, or LaTeX compiling it before the revert -- no longer breaks the open document.  A save then keeps the document open: pages, cached images and annotation names stay valid.  New option ~pdf-view-close-idle-documents-after~ (30 minutes) closes the document of a buffer that has shown in no window that long.  Also fix(roll): a window that shows the buffer again after a close draws its pages anew.
- =fix/server-wrong-password-crash=, on top of =feat/documents-in-memory=: fix(server): open a document through ~poppler_document_new_from_stream~ before poppler-glib 26.02, since ~poppler_document_new_from_bytes~ and ~poppler_document_new_from_data~ there crash on a wrong password (CI on Ubuntu, poppler 24.02 and 26.01).  Also test: an RSA test key, since GnuPG 2.5.24 cannot decrypt with the cv25519 subkey it imports (CI on macOS).
- =fix/virtual-close-on-kill=: fix(virtual): close the documents of a virtual PDF when it is killed.  The files a VPDF buffer showed stayed open in the server after the buffer was killed; now those that no buffer visits are closed.
- =feat/epdfinfo-version=: epdfinfo reports its version, 1.0.0, with the new ~version~ command and with =epdfinfo --version=.  When the server starts, pdf-tools compares it with ~pdf-info-epdfinfo-version~; if the program is older, or has a higher major number, Emacs warns once per session and uses the program anyway.  =M-x pdf-tools-install= offers to rebuild an older epdfinfo, and activates PDF Tools with it if you decline or the build fails.
- =feat/skip-large-file-warning=: Emacs no longer asks for confirmation before opening a PDF file larger than ~large-file-warning-threshold~, through an ~:around~ advice on ~abort-if-file-too-large~ that ~pdf-loader-install~ and ~pdf-tools-install~ install.  New option ~pdf-tools-warn-about-large-files~, nil by default; set it to t to have Emacs ask again.
- =feat/protect-unsaved-documents=: ~pdf-info-quit~ is a command.  Run with =M-x=, it does not quit epdfinfo while a PDF buffer has unsaved changes, e.g. edited annotations, which exist only in the server until the buffer is saved; a warning names those buffers, each a link to the buffer.  ~pdf-tools-uninstall~ makes the same check.  Called from Lisp, ~pdf-info-quit~ quits without it.
- =feat/stateless-render-options=: epdfinfo 1.1.0 takes the ~:render/~ options with each ~renderpage~ and ~boundingbox~ request, and pdf-tools sends the options of the buffer's themed, midnight and printer modes with each render, so a page renders the same after the server is restarted.  With an older epdfinfo they are set with ~setoptions~ as before.  Turning the midnight mode off while the themed mode is on shows the theme's colors.
- =feat/remember-document-password=: fix(info): the buffer keeps the password of an encrypted document in ~pdf-info-document-passwords~, and a request that fails with "Document is encrypted" opens the document with it and is sent again.  An encrypted document failed after a restart of epdfinfo and after ~pdf-view-close-idle-documents~ closed it.
- =feat/restart-after-rebuild=: new command ~pdf-info-restart-server~ restarts epdfinfo, unless a PDF buffer has unsaved changes; open buffers go on with the new server.  After building epdfinfo, =M-x pdf-tools-install= asks whether to restart the running server with the new program.  Also fix(info), on =feat/stateless-render-options=: with an epdfinfo older than 1.1.0, turning on a color mode failed with "Missing a option value".
